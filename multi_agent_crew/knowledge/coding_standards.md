# Python 编码规范速查(供 RAG 检索)

## 可读性与简洁
- 好品味优先:消除特殊情况,让逻辑自然;一个函数只做一件事。
- 优先标准库;避免引入不必要依赖与过早抽象。
- 命名表意清晰,注释解释「为什么」而非「是什么」。

## 类型与文档
- 公开函数/方法都要有类型注解和简短 docstring(说明参数、返回、异常)。
- 用 dataclass / pydantic 表达数据结构,而不是散落字典。

## 健壮性
- 显式处理边界:空输入、None、超大输入、并发、资源释放。
- raise 具体异常类型,不要裸 except;失败信息要有上下文。
- 涉及外部资源(文件/网络/锁)要幂等且可重入。

## 测试
- pytest 风格;每个公开行为至少一个正常路径用例 + 关键边界用例。
- 测试只依赖公开接口,不断言内部实现细节;用 tmp_path 等 fixture 隔离副作用。

## 兼容性
- 不破坏已有公开接口;改动保持向后兼容。
